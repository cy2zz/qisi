## RDS 严格 TLS 配置切片（2026-09-17）

状态：A01 仍为 `in_progress`；本切片仅完成已确认 RDS 的 CA 信任链与 NestJS 连接配置，不代表 StorePort、完整迁移或 ST01–ST04 完成。

Specify：正式 RDS 实际库名为 `qisi-easy`。公共 CA 固定放入 `server/certs/ApsaraDB-CA-Chain.pem`，默认相对路径为 `certs/ApsaraDB-CA-Chain.pem`；本地通过 `npm --prefix server ...` 运行时工作目录为 `server/`，容器工作目录为 `/app`。启用 `DB_SSL` 时必须读取该 CA，并保持 `rejectUnauthorized: true`。CA 是公共信任材料，可进入仓库与镜像；数据库密码继续只由 Git 忽略的环境文件或部署环境注入。

失败先行：`npm --prefix server test -- src/config/env.spec.ts src/database/database.factory.spec.ts` 首次退出 1，5 项中 3 项失败，分别证明旧库名正则拒绝连字符、配置缺少 CA 路径、mysql2 未收到 CA。

实现：库名校验允许安全的字母、数字、下划线和连字符；新增可覆盖且默认指向 server 公共证书的 `DB_SSL_CA_PATH`；数据库 factory 在 TLS 开启时同步读取 CA 并传入 mysql2；DatabaseService 完整传递配置；正式镜像复制 `certs/`。Git 忽略的本地/正式环境文件仅把库名改为真实的 `qisi-easy`，未写入或输出凭据。

验证：定向测试退出 0（2 files、5 tests）；完整 server test 退出 0（3 files、6 tests）；typecheck、lint、build 均退出 0。`openssl crl2pkcs7 ... | openssl pkcs7 ...` 成功解析证书链。NestJS 以 production 配置启动后，`GET http://127.0.0.1:3000/api/health/ready` 返回 HTTP 200 与 `{"status":"ready"}`，只执行现有 `select 1`，未运行迁移、DDL 或 seed。Docker CLI 不可用，镜像构建和 Compose 运行未执行。

证书来源：阿里云官方 `ApsaraDB-CA-Chain.zip`；当前 PEM 为 156799 bytes、81 张证书。外部 CLI 连接已确认 RDS 为 MySQL 8.4.7、TLSv1.3，并可通过 `VERIFY_IDENTITY`；凭据不进入证据。
