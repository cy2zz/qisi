# A04｜独立检验状态、计划锁定与同题求助

Task ID：A04（`implemented_waiting_review`；单 AI `self_review`，未完成独立复核）。基线：qisi-3.1。需求：FR11、FR12；验收：AT30、AT31、AT32。

当前学习时刻：学生已经完成原题教学，需要用一道未见的近迁移题检验能否独立迁移。页面先锁定首次计划，再开放最终答案；提交前不显示对错。学生可以随时求助，但确认求助后本次独立资格不可恢复，原题、当前草稿和求助状态必须跨刷新保留。

不变量：参考答案与 rubric 只留在服务端；计划锁定后不可修改；最终答案首次提交即冻结；评分失败只恢复评分，不重新开放答案；任务是否未见、是否近迁移、是否请求或实际获得帮助均由服务端持久状态决定，模型不能直接设置独立通过。`assistance_requested` 与 `help_exposed` 分开：请求求助先持久化，只有同题教学中经过 Guard 的教师回复成功提交才记为实际帮助。

失败先行：页面测试先要求求助响应必须提供“进入同题教学”链接；真实 MySQL 校验先要求求助会话保留检验题和草稿，并在首条教学回复提交后更新 `help_exposed`。实现前 Web 定向测试 2 项中 1 项失败，server typecheck 因 `helpSessionId` 不存在失败。

实现：新增 `assessment_tasks`、`seen_tasks`、`check_attempts` 三张表及稳定迁移；Assessment 服务生成近迁移题后执行独立 Guard 复核，owner 级登记 task hash 与 equivalence group，完成计划草稿、首次计划锁定、答案草稿、最终答案冻结、评分恢复和 owner/version 隔离。评分器与 Guard 分别核对规划和执行，独立性由代码结合首次资格、任务关系、求助、实际帮助和失效状态计算。

## 2026-09-20 独立检验失败后的修正优先级

独立检验总结不再把“继续换题”作为所有结果的统一主操作。顶部结论先区分方法错误、执行错误、未作答、证据不足和“答案有依据但独立资格不成立”，不再用同一句“没有同时覆盖计划与执行”混淆不同原因。页面随后按已冻结证据分流：首次计划不是 `correct` 时先回学习页梳理方法；计划正确但执行不是 `correct` 时先处理执行卡点；计划与执行均有依据、但因帮助或资格边界仍未形成独立通过时，先查看证据边界。只有 `independentTaskPass=true` 时，“再测一道不同的新题”继续作为首要动作。未通过时仍保留“换题再测”，但降为次要入口，避免用连续刷题绕过尚未修正的错误。

视觉继续使用既有答题纸与思路轨道：在结论边界之后增加一条无卡片包裹的下一步轨道，PC 保持证据与行动的主次关系，H5 将修正入口单独占满一行，学习报告和换题入口置于下一行；全部触控操作不低于 44px，360/390 均无根页面横向溢出。`qisi-student-ui` 用于约束错误中性表达、证据不夸大和 PC/H5 同语义；`frontend-design` 用于维持克制的纸面层级，不增加后台式卡片堆叠。

## 2026-09-20 修正类型进入真实教学轮

此前跨页衔接只把修正起点写进草稿，URL 清理后服务端无法区分“方法修正、执行修正、证据边界”，教师回复可能重新退化为普通聊天。本轮把学生显式选择保留为一次性的受控 `remediationFocus`：编辑器上方持续显示本轮唯一目标，发送时才随请求提交，发送后转为教师消息上的修正标签；退出修正模式不会删除学生已经写下的内容。

服务端只接受 `method|execution|evidence`，将对应边界同时交给 Strategy 与 Guard。方法修正只补选法与依据；执行修正在诊断证据仍支持原方法时只定位第一处计算、变形或表达偏差；证据边界只解释为什么不能记为独立通过。回流标记仅限制反馈范围，不是掌握事实，证据矛盾时必须中性说明证据不足。该类型进入请求幂等哈希、run 审计、公开消息 metadata 和教学事件，刷新后仍能恢复修正标签，但不会绕过现有帮助曝光与独立检验规则。

失败先行：PC 1280 回流测试找不到“本轮修正目标”；服务测试也无法在 Strategy 输入中找到执行修正边界。实现后服务端定向 3 files / 28 tests、三类 Strategy/Guard 边界和非法枚举拒绝均通过；跨页四视口 4/4，H5 退出修正操作 ≥44px、360/390 无横向溢出。Web 20 files / 75 tests、Server 45 files / 342 tests、两端 typecheck/lint/build 均通过。完整 Playwright 首轮 71/72，唯一 PC 1280 专注读题点击在并行负载下超时，隔离复跑 1/1 通过；随后完整干净复跑 72/72。视觉证据为 `A04-remediation-turn-pc-1440.png` 与 `A04-remediation-turn-h5-390.png`。`real_student_observation: not_run`。

## 2026-09-20 可恢复的持续修正轨道

一次修正回复不再自动结束方法、执行或证据修正。学生后续普通作答、最小提示和最终核对继续携带同一受控范围；只有学生显式退出，或在 `finish_problem` 中得到结构化 `correct`，轨道才关闭。`incorrect` 与 `unknown` 继续保留范围，修正完成仍不等于掌握，下一主路径仍是新题独立检验。

修正激活和退出写入 owner-scoped `remediation_track_updated` 事件，并与会话 `next_event_seq` 在同一事务推进；每次成功教学提交也在同一事务刷新轨道状态。刷新从最新有效事件恢复，另一用户不能读取或改写。退出失败不会只在界面假装成功，而是保留轨道并提示重试。

视觉复核发现 H5 同时堆叠普通帮助、核对栏和修正栏会压缩反馈空间。修正态现在收起普通帮助与通用核对栏，只显示“当前修正范围 + 核对修正结果 + 退出修正模式”的专用操作带；360/390 下说明在上、两个完整 44px 操作并排在下，PC 保持紧凑横向轨道。

失败先行：PC 1280 首次在激活后未写入持久状态，`persistedRemediationFocus` 5 秒内始终为 `null`，退出 1。实现后四视口证明第二次普通提交仍携带 `execution`、刷新后轨道恢复、显式退出后下一次请求不再携带该字段。Web 20 files / 75 tests，Server 46 files / 345 tests，两端 typecheck/lint/build，完整 Playwright 72/72 均退出 0；真实本地 MySQL 8.0.45 输出 `remediationRestore=true`、`remediationExit=true`、`remediationOwnerIsolation=true`。视觉证据：`A04-remediation-track-pc-1440.png`、`A04-remediation-track-h5-390.png`。正式 MySQL 8.4、独立复核与真实学生观察仍未执行，`real_student_observation: not_run`。

## 2026-09-20 独立检验断网草稿保护

独立检验的首次计划和最终答案现在与教学草稿共享同一套有界本机缓存内核，但按 `attempt_id + check_plan|check_answer` 分键保存。每次文字、公式快捷输入或已确认手写写回编辑器时立即更新本机副本；服务端保存成功后清理对应阶段。刷新时必须先成功读取 owner-scoped attempt，才允许恢复同 attempt、同阶段且 24 小时内的本机副本；计划锁定、最终提交或求助持久化成功后只清理已经完成的阶段。空草稿继续作为未同步 tombstone，避免旧云端内容重新出现。

服务端 503 时页面不再用告警打断学生，而显示“已保存在本机，等待网络恢复”；刷新恢复显示“已恢复本机草稿，尚未同步”。学生可用 44px“立即同步”，浏览器 `online` 事件也会补传原始 Markdown。恢复和补传不会锁定计划、提交最终答案、请求帮助、评分，也不会改变 `firstSeenEligible`、版本、帮助曝光或独立通过结论；本机存储不可用时仍保持页面草稿并回到原有显式错误状态。

失败先行用例先因找不到本机保存状态退出 1。实现后缓存与页面组件 3 files / 21 tests、Web 全量 24 files / 111 tests、A04 断网四视口 4/4、键盘四视口 4/4、完整 Playwright 100/100，以及 typecheck、lint、build、`git diff --check` 全部退出 0。视觉证据为 `A04-offline-draft-pc-1440.png`、`A04-offline-draft-h5-390.png`；fixture/mock 网络故障验证，`self_review`，未提交、未推送，`real_student_observation: not_run`。
