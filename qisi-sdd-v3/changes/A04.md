# A04｜独立检验状态、计划锁定与同题求助

Task ID：A04（`implemented_waiting_review`；单 AI `self_review`，未完成独立复核）。基线：qisi-3.1。需求：FR11、FR12；验收：AT30、AT31、AT32。

当前学习时刻：学生已经完成原题教学，需要用一道未见的近迁移题检验能否独立迁移。页面先锁定首次计划，再开放最终答案；提交前不显示对错。学生可以随时求助，但确认求助后本次独立资格不可恢复，原题、当前草稿和求助状态必须跨刷新保留。

不变量：参考答案与 rubric 只留在服务端；计划锁定后不可修改；最终答案首次提交即冻结；评分失败只恢复评分，不重新开放答案；任务是否未见、是否近迁移、是否请求或实际获得帮助均由服务端持久状态决定，模型不能直接设置独立通过。`assistance_requested` 与 `help_exposed` 分开：请求求助先持久化，只有同题教学中经过 Guard 的教师回复成功提交才记为实际帮助。

失败先行：页面测试先要求求助响应必须提供“进入同题教学”链接；真实 MySQL 校验先要求求助会话保留检验题和草稿，并在首条教学回复提交后更新 `help_exposed`。实现前 Web 定向测试 2 项中 1 项失败，server typecheck 因 `helpSessionId` 不存在失败。

实现：新增 `assessment_tasks`、`seen_tasks`、`check_attempts` 三张表及稳定迁移；Assessment 服务生成近迁移题后执行独立 Guard 复核，owner 级登记 task hash 与 equivalence group，完成计划草稿、首次计划锁定、答案草稿、最终答案冻结、评分恢复和 owner/version 隔离。评分器与 Guard 分别核对规划和执行，独立性由代码结合首次资格、任务关系、求助、实际帮助和失效状态计算。

求助闭环：确认求助事务内先保存当前草稿和 `assistance_requested=true`，再创建 owner-scoped 同题教学会话。会话沿用检验题题干并携带学生草稿，只显示中性的帮助边界，不预先展示解法；页面一键进入 `/study?session=<id>`，PC/H5 均恢复指定会话而非误开最近的其他题。教学回复提交事务通过会话事件关联回检验 attempt，并且只在安全回复真正持久化时把 `help_exposed` 从 false 更新为 true；provider/Guard 失败不会假记曝光。

验证：真实 MySQL 8.0.45 已覆盖 owner 隔离、CAS 旧写拒绝、评分恢复、exact task 与 equivalence group 重选拒绝、同题求助会话、请求/曝光分离。AT32 跨页 Playwright 在 PC 1440/1280 与 H5 390/360 共 4 项通过；独立检验完整四视口链路此前已验证计划锁定、刷新恢复、最终评分和无私有材料泄漏。Web/Server typecheck、lint、相关单元测试通过。
