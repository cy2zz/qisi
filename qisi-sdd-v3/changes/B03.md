## 2026-09-19 本题判定与独立检验门禁

失败先行发现 `finish_problem` 的回复即使明确写着“当前结论需要修正”，页面仍固定显示“换一道题独立检验”。这会把“完成一次模型核对”误画成“当前答案正确”，并让错误答案越过本题修正阶段。修复不解析教师自然语言，而是沿用 Diagnosis 已产生的结构化 `currentVerdict: correct | incorrect | unknown`：Controller 只在事务提交后随 SSE `done` 发送该字段；`LearningSessionService` 将其写入 guide message metadata、`current_answer_checked` 事件和幂等 safe response，刷新与同 request replay 均保持同一判定。

学生端仅在 `correct` 时显示“换一道题独立检验”，并继续声明“本题结论正确不等于已掌握”；`incorrect` 显示“继续修改这次答案”，`unknown` 显示“补充一行关键依据”，两者都不产生独立检验链接。三态同时使用文字、证据条和 jade/amber/cobalt 语义，不只依赖颜色；修正入口保持 44px 触控高度并把焦点交回输入框。旧消息缺少 verdict 时安全落到 `unknown`，不会误放行。

当同一题有多次核对时，只有最新一次核对保留下一步操作；更早的结论卡仍作为学习轨迹可见，但动作替换为“已由后续作答更新”，避免学生点击已经过期的“继续修改”或独立检验入口。

每张结论卡的“帮助记录”按该条消息所在时间点累计，不再读取会话最终的全量帮助集合。这样后来发生的局部解释或直接讲解不会倒灌到更早的作答证据，保留“学生当时在多少帮助下完成”的真实顺序。

验证：server analysis 定向 2 files / 21 tests、web App 9 tests、真实本地 MySQL persistence 均退出 0，持久化输出含 `verdictReplay=true`；B03 Playwright 在 PC 1440/1280、H5 390/360 共 8/8 通过，先验证错误结论无独立检验链接，再修改为正确结论后验证入口出现。Web 全量 18 files / 59 tests、typecheck/lint/build 通过；server typecheck/lint/build 通过。server 全量 314 项中 302 passed，12 个失败仍只来自已有 prompt CRLF/LF 逐字节差异。没有真实学生观察。
