当前学习时刻：学生完成读题后，选择自己尝试、最小提示、局部解释或直接讲解。学生主操作是留下自己的依据；主要压力来自“不会开始”和“担心提示直接把题做完”。帮助披露风险是最小提示泄露答案或关键端点判断；失败恢复必须保留原帮助深度，未经 Guard 的候选回复不得进入 HTTP 流。

输入 / 输出：浏览器向 `POST /api/problems/chat` 提交 `attempt | hint | explain | worked_solution`、当前学生消息、最近可见历史和当前题目 Markdown。策略模型产生候选回复后，独立 `guard` 角色核对数学可靠性和帮助深度；只有 `accept` 才返回候选，`reject` 使用按帮助模式区分的中性安全回退。前端对每条教师回复显示“思路反馈 / 最小提示 / 局部解释 / 直接讲解”标签，重试保持原模式。

不变量：hint 不得给最终答案、下一计算结果、完成表达式、具体端点取舍或决定性步骤；explain 只解释局部卡点；attempt 不代替学生完成关键判断；worked_solution 仍拒绝数学不确定、系统信息、私有评分依据和不可信 HTML。模型候选在 Guard 通过前不流向浏览器；Guard 无法给出合法结构时整轮失败，不静默放行。

写集说明：正式 B03 独占写集要求 `server/src/features/tutor/**`、`web/src/pages/learn/SessionPage.tsx` 与 `server/src/workflows/turn.ts`。当前运行产品尚未存在这些页面/feature，真实入口是既有 `server/src/features/analysis/**` 与 `web/src/pages/bank/BankFlow.tsx`。本轮只在用户已授权的当前可用纵向链路上加入兼容 Guard，并记录迁移缺口；未修改 Assessment、正式工作流 StorePort 或 prompts 文件，未把 `tasks.json` 标为完成。
