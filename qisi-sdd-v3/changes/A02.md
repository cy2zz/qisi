失败测试计划：已有 Cookie 和新登录都必须进入 `/bank`；PC 必须显示左侧导航/当前页面做题记录和右侧答题区，H5 必须通过抽屉提供同等入口；学生可以直接输入题目或从本地夹具选择；公式快捷项必须向输入框插入可预览的 LaTeX；四个规定视口不得产生横向溢出，中文字体栈以 Microsoft YaHei 开头。

实际失败证据：首次 `npm test` 退出 1，2 个既有登录断言和 1 个新主链断言失败，证明页面仍停在登录欢迎态且没有选题入口；首次 A02 Playwright 运行 4 项中 PC 2 项通过、H5 2 项因横向溢出失败。第二版视觉重构前 A02 Playwright 4/4 因字体/双栏断言失败。对话工作台重构前，定向 Vitest 退出 1（3 failed / 1 passed），A02 Playwright 退出 1（4/4 failed），均因新的对话工作台、本地题库和公式输入尚不存在。一问一答增量失败测试中，服务端 1/3 失败（`reply` 不存在），前端 1/5 失败（发送后没有流式状态），证明旧实现只记录学生文本而不会调用 AI 回复。

实现与迁移：登录成功与 Cookie 恢复后统一进入 `/bank`。该页改为极简数学对话工作台：PC 左栏上部为新题/当前对话/本地题库导航，下部为当前页面做题记录；右侧为对话流和固定输入坞。学生可直接输入题目，或从三道明确标注的本地自拟夹具中选择；公式工具栏插入分式、根式、上下标、积分和极限 LaTeX，并通过既有安全 KaTeX 链路预览。选择或首次输入题目后，前端自动请求服务端分析并展示加载、结构化结果、失败和重试状态。此后每条学生消息都调用服务端 AI，携带当前题目和最近 16 条已展示问答；同一时刻只允许一轮在途请求，新题会中止旧请求。服务端以 OpenAI-compatible `ModelPort` 调用已配置 provider，60 秒超时、无自动重试，严格校验 provider 包装与 `{reply}` JSON 后才通过 SSE 分片，不向页面流出未检查 token。前端逐片追加文字、显示光标和真实等待状态，完成后再用安全 Markdown/KaTeX 渲染；错误保留学生消息并可重新回答。H5 以导航抽屉提供相同入口，输入、题库、公式、分析和连续问答能力不裁减。当前对话与记录只保存在 React 页面状态，界面明确说明未持久化；完整诊断/策略/Guard 工作流仍未接入。
