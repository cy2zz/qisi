# B04｜证据诊断与探针预算纵向切片

Task ID：B04（`in_progress`；typed Submission 证据校验、持久探针预算、预存分支和同错不同因真实模型评估已接入，手写 revision 未完成）

需求 / 验收：FR08；AT19、AT20、AT21、AT23 `passed_self_review`，AT22 `partial`。

Specify：每次 Diagnosis 只能引用当前会话中已确认、未失效且 revision 精确匹配的学生输入，quote 必须真实存在；模型生成的 focus/probe goal 必须来自当前稳定路线。已真实显示的探针按 canonical goal 累积且刷新后恢复，两次后模型即使更换 goal/node 标识也不得继续追问。将要显示的探针必须在公开 SSE chunk 之前，把 question、expected、counter_evidence、next_action 原子写入 MySQL。

写集与现状：规格目标路径为 `features/tutor/evidence.ts`，当前真实运行入口位于 `features/analysis/**` 与 `features/learning/**`；本轮在该纵向入口实现并记录迁移差异，没有修改 Assessment 业务或 DDL。事件复用现有 `events` 表，不建立第二套状态源。

失败先行：新增虚构 submission 引用用例先实际通过了错误诊断，证明仅有 Zod 结构不足；新增 canonical goal 变更用例用于证明换 ID 不能重置预算；持久化验证要求下一轮恢复曝光与探针次数，并读取两条预存分支。

实现：Diagnosis 结构结果在节点标记 completed 前执行证据语义校验；缺 submission、revision、quote、未知 decision 或不稳定 goal 使节点记录为 failed，Strategy 不再调用。Strategy 接收从 `help_exposed` 事件恢复的实际 Exposure 与剩余探针预算。PolicyGate 同时校验 known goal、focus/probe 一致性和两探针上限。成功提交把实际披露决策写入 `help_exposed`，把完整探针问题和预设分支写入 `diagnostic_probe_shown`；Controller 先完成事务提交再发送首个公开 chunk，失败提交不会展示探针。公开 session 响应不返回私有探针分支。

验证：定向 4 files / 39 tests 通过；新增 Controller 提交顺序用例通过；server typecheck/lint/build 通过。真实本地 MySQL 8.0.45 验证输出 `exposures=1, probes=1, replay=true, ownerIsolation=true`，并实际回读 question 与两条 expected/counter/next_action 分支。真实 provider 普通教学轮继续保持 Diagnosis → Strategy → Renderer → Guard，模型 `gpt-5.5-2026-04-24`，四节点 usage 均为 reported。2026-09-20 又以相同正式提示、严格 Schema 和真实 provider 直接执行 Diagnosis → Strategy 三组对照：错误规则为 `concept:supported`，抄写失误为 `execution:supported` 且 `concept:refuted`，符号到单调性的连接卡点为 `strategy:supported`；三组均为 L1，概念/执行教学动作不同，连接卡点没有重教求导。直接评估不依赖当前缺少 workflow 表的业务库，避免把数据库迁移阻塞误报为模型质量失败。
