# 验收与教学评测执行协议

基线qisi-3.0；本文是待执行协议，不是评测结果。验收用例见cases.json，行为轨迹见fixtures/branch-cases.json。模型评审须记录原始输出、调用预算与人工复核，不能用规格校验替代。

## 1. 四类证据严格分开

| 层 | 证明范围 | 不能证明 | 执行方式 |
|---|---|---|---|
| 规格静态校验 | 引用、Schema、夹具、部分业务不变量、SQL语法一致 | 应用能运行、模型有效、学生学会 | 本包python scripts/validate_spec.py |
| 应用确定性验收 | 真UI/DB/Server Action/故障恢复按契约工作 | 真实模型教学能力 | 应用内unit/integration/Playwright；FixtureProvider明确标识 |
| 真实模型教学评审 | 固定版本模型对所测样本满足标准 | 真实学生学习收益与因果效应 | REAL_MODEL=1；角色与会话回归；人工按盲化量表复核 |
| 真实学习观察 | 受试者在所测任务的独立产物表现 | 普遍提分、长期掌握、无对照的因果结论 | 知情同意、匿名数据、帮助记录、未曝光检验；未开展记not_evaluated |

## 2. 开发测试注册

A01实现tests/coverage-manifest.json：AT ID -> 文件/测试title/层/是否需真人模型。任务脚本不能将缺测试、0测试、跳过、未配置key当作通过。result-template.json中默认not_run；运行者填写commit、时间、环境、题库范围、模型/提示词版本、实际结果与证据路径。人工项只由实际评审者签字更新。

所有60项AT须有最终处理：passed或明确failed/blocked/not_run，不允许从报告隐藏失败项。发布时P0确定性验收不能残留失败；模型关键错误必须修复并回归；真人学习实验不是功能发布前置条件，但未进行时不得宣称已证明学会。

## 3. 全题库与随机能力

1. 取得主办方题库并冻结manifest，报告总记录数、完整导入数、异常数和每条异常原因。全量做结构/图片/来源/内容哈希核验；不将异常条目从随机池悄悄删除。
2. A08/B08共同选至少12题或较小题库全量进行深度教学评审，覆盖题库实际存在的主要专题、难度、图形/多问/开放证明类型。若某类不存在报告N/A；样本不足如实记录，不用自拟题凑真题数。
3. 样本一部分由固定seed/manifest可复现抽取，一部分按类型补齐；发布报告同时列抽样法、入选ID和全题库分母。实际产品随机由服务端crypto.randomInt执行，不强制使用测试seed。
4. 按选中ID从冷准备到教学到独立检验跑完整链路。准备失败、未知数学结论、图片缺失、超时均留在分母；人工修复必须产生新版本并保存修复前失败。
5. 十二题只能提供有限覆盖证据，不代表所有高考题可靠。主办方题库未提供时，真题覆盖验收保持blocked_external。

## 4. 角色与分支回归

四Agent+Renderer/Guard每个至少执行role-cases.json规定的正反例；实际输出使用严格Schema和跨字段规则检验。随后执行BT01–BT16，每条保存输入、预注册预期分支、真实输出、Guard结果、显示文本、状态/曝光变化。

关键教学对照：完全相同错误表达，在后续证据分别支持概念误解/执行失误时，诊断和干预必须分化；证据不够先unknown而非乱贴标签。异解、跳阶、反证、两探针上限、OCR更正、帮助失败、重测、删会话均不能仅用理想对话视频覆盖。

模型随机性：固定记录temperature等实际支持参数；每种关键风险至少3次独立运行，不能只挑最好一次。JSON格式自动验证，教学是否泄露/误诊/过度提示由两名开发者独立标注；分歧保留并共同复核，不能以另一个LLM裁决代替人工标准。

## 5. 强基线与改进判据

基线是认真设计的单Agent苏格拉底老师，包含同样的数学参考、学生证据和安全规则，不是弱化的“直接给答案”聊天。与本方案使用同一模型版本、同一题目/输入脚本、同一最大总token/时限/允许帮助等级；比较多Agent系统总成本而非单次调用成本。评审时隐藏系统名称，保留展示顺序。

记录指标而不预填结果：
- 诊断：有可定位证据的正确归因数/可判定机会数；unknown单列；错误归因数/全部机会数。
- 干预：符合诊断且保留有效学生决策的干预数/全部实际干预数；多余追问单列。
- 自主性：学生真实产物支持且此前未受对应帮助的决策数/已评决策数；这是过程指标，不是掌握率。
- 保护：答案泄露、虚构引文、伪装独立通过、把不同有效解判错、OCR未确认就教学分别计数。
- 检验：规划/执行/整题独立通过分别报告，同时列帮助、跳过、unknown、未测；不能只报告作业正确率。
- 工程：准备失败率、实际调用/token总数、总时延p50/p95、恢复重复计费情况。

同题脚本比较只能说明系统行为，不能说明真人学习效果。若多Agent较基线没有稳定优势，优先改诊断探针/上下文/策略，不为架构复杂而保留无收益调用。核心Agent责任边界仍保留，允许减少非必要调用。不得预设“必定优于单Agent”的发布结论。

## 6. 学习证据与人工观察

可选小规模观察必须获得同意，未成年人遵循组织要求取得适当监护/机构同意，最小化采集身份信息。参与者先独立尝试，再教学，最后面对本系统保存期内未曝光的已核对近迁移题，先锁计划再提交解答；不在锁计划前暗示方法，不在结束前给正确性反馈。

为了避免测试顺序污染，同一参与者不在两套系统中重复同题；用经人工核对的匹配题组及平衡顺序，说明能力差异与题目不等难等限制。自拟fixture第二题难度不同，不能直接充当匹配研究工具。

原题完成、重复同题正确、带帮助正确、近迁移一次正确、延迟/远迁移分别呈现。未做延迟测验固定not_evaluated。报告显示匿名owner与外部帮助无法全追踪的边界。没有真人数据只演示“证据采集机制”，不能展示虚构提分率或掌握百分比。

## 7. 交付门禁与演示

A10负责安装/部署/数据/可回滚；B10负责提示词版本/真实模型/教学质量。共同跑随机题冷启动、手写确认、同错不同因、异解/跳阶、独立检验、求助后新题重测、教师依据、超时恢复/删除。预录视频仅备用，实时失败须明确承认。

任何P0功能不能因第10天到来直接降级删除。若依赖受阻，给出剩余项、责任人和预计工作量；计划日期顺延。必须区分“规格可交付”“应用可演示”“教学质量已评审”“学习效果已有证据”四种状态。
