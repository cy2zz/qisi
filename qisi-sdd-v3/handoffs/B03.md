### 实测发现两个真实缺陷（此前无法发现，因为从未接过真实 provider）

**① 上游 400：`response_format: json_object` 要求 messages 含 "json"**

A 的适配器无条件设置 `response_format: {type:'json_object'}`，而 OpenAI 兼容网关要求 messages 中出现 "json" 字样，否则返回：

```
400 'messages' must contain the word 'json' in some form, to use 'response_format' of type 'json_object'
```

规格包的角色提示（`qisi-sdd-v3/prompts/*.md`）通篇不含 "json"——它们用中文写「仅返回目标Schema允许字段」。**两者直接组合会让每个角色、每次调用都 400。**

**② `outputSchema` 从未告知模型（这是 B01 自身的设计缺口）**

B 的 `ModelRequest.outputSchema` 只用于**事后校验**，从未下发给模型；而上游接口也不接收该字段。规格包的角色提示是中文散文，不含任何字段名。实测中模型据此自造字段：

```
实际返回 hypotheses[].gap_type / description / probe.question / expected_evidence
契约要求 hypotheses[].kind / explanation / missing_evidence / probe.goal_key / question_md / branches
```

结构校验必然失败，且修复重试也无效——重试只是把校验错误回注，模型仍不知道正确字段名。

**两者的修复都在桥接层**（`buildUpstreamSystem`）：把 `z.toJSONSchema(outputSchema)` 转成 draft 2020-12 注入 system，同时满足上面两条。不在提示词里补，是因为提示词与规格包逐字节一致是 B01 建立的保证、由 `prompts.spec.ts` 三方比对守住；这两条约束都是上游请求形态带来的，属桥接层职责。

### 实测发现两个真实缺陷（此前无法发现，因为从未接过真实 provider）

**① 上游 400：`response_format: json_object` 要求 messages 含 "json"**

A 的适配器无条件设置 `response_format: {type:'json_object'}`，而 OpenAI 兼容网关要求 messages 中出现 "json" 字样，否则返回：

```
400 'messages' must contain the word 'json' in some form, to use 'response_format' of type 'json_object'
```

规格包的角色提示（`qisi-sdd-v3/prompts/*.md`）通篇不含 "json"——它们用中文写「仅返回目标Schema允许字段」。**两者直接组合会让每个角色、每次调用都 400。**

**② `outputSchema` 从未告知模型（这是 B01 自身的设计缺口）**

B 的 `ModelRequest.outputSchema` 只用于**事后校验**，从未下发给模型；而上游接口也不接收该字段。规格包的角色提示是中文散文，不含任何字段名。实测中模型据此自造字段：

```
实际返回 hypotheses[].gap_type / description / probe.question / expected_evidence
契约要求 hypotheses[].kind / explanation / missing_evidence / probe.goal_key / question_md / branches
```

结构校验必然失败，且修复重试也无效——重试只是把校验错误回注，模型仍不知道正确字段名。

**两者的修复都在桥接层**（`buildUpstreamSystem`）：把 `z.toJSONSchema(outputSchema)` 转成 draft 2020-12 注入 system，同时满足上面两条。不在提示词里补，是因为提示词与规格包逐字节一致是 B01 建立的保证、由 `prompts.spec.ts` 三方比对守住；这两条约束都是上游请求形态带来的，属桥接层职责。
