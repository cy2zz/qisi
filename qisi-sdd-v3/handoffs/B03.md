## 附带交付：server/db 下的建表 SQL（未经真实 MySQL 验证）

按项目方指定的位置约定，新增 6 张 B 侧所需的表：

| 文件 | 表 | 用途 |
| --- | --- | --- |
| `server/db/10_requests.sql` | `requests` | `StorePort.reserve` 的幂等键 |
| `server/db/20_runs.sql` | `runs` | lease / fencing / deadline |
| `server/db/30_node_runs.sql` | `node_runs` | `getReusableNode` / `saveNode` |
| `server/db/40_events.sql` | `events` | `commitChecked` 的原子事件写入 |
| `server/db/50_packets.sql` | `packets` | B02 包缓存（按 `problem_hash` + 版本） |
| `server/db/60_probe_counters.sql` | `probe_counters` | B03 探针计数，含 `CHECK(shown_count BETWEEN 0 AND 2)` |

DDL 逐字取自 `qisi-sdd-v3/contracts/database.sql`，仅在以下两点做了调整：

1. **移除跨领域外键**（`requests`/`runs`/`events`/`probe_counters` → `sessions`、`owners`）。原因：`sessions` 尚未建表，`owners` A 当前实现为 `users`。每个文件头部注明了被移除的外键原文，A 建好对应表后由后续迁移补加。`runs` 与 `requests` 的复合外键、`node_runs` → `runs` 的外键为 B 内部依赖，已保留。
2. **文件名加数字前缀**（`10_`–`60_`）。原因：`SqlMigrationProvider` 按文件名字母序返回迁移，而 `node_runs` 字母序排在 `runs` 之前，外键会建失败。前缀使依赖顺序显式。注意这与 A 已有的 `db/users.sql`（无前缀）风格不一致——`users` 无外键依赖，不受影响。

**未验证声明**：项目方明确要求本次不执行 `db:migrate:dev`，因此**这批 DDL 未经真实 MySQL 执行**。它们是从规格包逐字派生并做了上述两处已知调整，但「照规格写」不等于「已跑通」。已知未验证项：语句在 MySQL 8.4.7 上的实际解析、`utf8mb4_0900_bin` 排序规则在建表时的接受度、`CHECK` 约束是否被实例真正强制。**在有人实际执行并回报之前，不得声称这 6 张表可用。**
