1. 最终要交付什么

不是“把答案拆成很多问句”，而是：面对题库中任意一道题，先理解学生已经会什么，通过少量有区分力的追问定位当前卡点，只给必要帮助，再用没有见过、没有提示的新任务检查学生能否自己规划和执行。

三个可演示的核心承诺：

同样一道错题、同样一行错误，因为后续证据不同，得到不同诊断和干预；信息不足时明确待定，不给永久能力标签。 台阶按关键决策拆分，而不是每一行运算拆分；学生会的地方能跳过，有效异解可走自己的路线。 原题做完不等于学会。报告分别显示原题帮助、新任务独立规划、新任务独立执行、证据不足和未验证项。

3. 产品流程与页面

3.1 题库页 /bank

显示完整题库与来源、主题、题图、准备状态。支持指定题、服务端均匀随机抽题、导入校验报告（教师）。随机默认覆盖当前题库全部ID，包括needs_review和invalid；选中异常题显示具体缺失与修复入口，不静默跳过。若评委明确指定子集，需先显示并确认范围，再记录范围哈希；不得以准备状态过滤。

拿到题库后全量建立清单与哈希，再异步/提前备课。题库未知时只能交自拟开发夹具，不能声称已经覆盖高考真题。冷启动准备页显示真实阶段及原题ID；失败仍保留原题，提供原题重试、人工修订，另选题必须用户明确触发。

3.2 学习页 /learn/[sessionId]

桌面三栏：题目与必要图、作答/对话、当前目标与已发生的学习记录。窄屏折叠三栏但不裁功能。

默认先请学生写自己的计划或已有步骤；提供“我不知道从哪开始”“给一点提示”“解释这个地方”“直接讲完整解法”按钮。允许立即请求解释，不强制先答错。不默认展示完整教师路线或未来关键结论。

学生以Markdown/LaTeX输入，或上传手写图逐行确认。可更正历史输入、提出不同路线、跳到自认为会的部分；系统用产物核对而不是只看“我会了”。每轮通常只提出一个可操作的问题。

3.3 独立检验页 /learn/[sessionId]/check

明确告知正在检查什么、该任务是否见过、是否允许帮助。先提交计划（可选择“暂时没有计划”，记unanswered），锁定后进入计算/证明作答；中间不反馈对错。最后一次提交后才评分。

学生可求助，立刻结束本次独立资格，保留当时作答快照，然后进入带帮助学习。重新检验必须用另一道经过核对且未曝光的任务，不重新命名旧题。

3.4 证据报告 /learn/[sessionId]/report 与历史 /history

列出“我自己提出的决策”“老师帮助过的决策”“当前已观察到的能力”“仍待验证”。分开原题完成、首次新任务规划与执行；不使用虚假掌握百分比或长期提分结论。历史只展示本匿名用户会话，不建设复杂账号系统；清除cookie后不能保证跨设备找回。

3.5 教师页 /teacher

独立鉴权后查看题库准备、当前会话决策依据、节点耗时/重试、版本和回归结果。点击打开当前任务教学依据前明确提示并记录该任务暴露；关闭抽屉、刷新不撤销暴露。不得提前返回未来检验题的答案。浏览器看不到私有解法并不等于开发日志可以无限保存学生内容。

4. 如何把题拆成有价值的台阶

4.1 两层图加一层检验

解题依赖图：决策节点、必要前提、可替代路线。单条路线内部使用AND前提，多条可行路线使用OR选择。 教学状态图：诊断探针、局部补偿、回到主线、合并/跳过台阶、撤架；重试可以发生，但不能让数学证明依赖成环。 新任务检验：另一任务ID、内容哈希、等价组、核对证据与首次曝光记录；不是原图最后一个“复述答案”的节点。

每个决策含：稳定goal_key、目标、进入条件、学生应交产物、核对标准、概念/执行/策略等候选卡点、依赖ID、route_id、source、当前谁完成了决策。不要由“第三问”机械推断“必须调用前两问”，必须注明调用的具体结论及适用条件。

4.2 动态拆分算法

备课Agent生成2–12个主决策（大型综合题可按小问分组，总计不超过24个），提供一条核对过的主路线；存在显著异解时列出替代路线。不是每题强凑两种解法。 学生先尝试。诊断Agent将有效产物对齐到现有目标，也允许提出未匹配路线；不能因不匹配判错。 新路线走route_review模式：核对数学与条件，生成局部图补丁。未核对则保持待定且不推送其后结论。每轮最多一次路线审查。 策略Agent选择一个当前焦点，需要时插入1–3个补偿节点；规范goal_key沿用原目标，不能借换ID重置探针预算。 完成后回主线；两次连续有效自主产物时尝试减少一级支架，错题则恢复必要帮助，不追求盲目降提示。

4.3 避免台阶变成牵线木偶

展开教师建议路线本身可能暴露策略，必须记账；不能一边把每一步都安排好，一边说学生独立规划。学生路线来源保留为student，教师插入部分为teacher，共同修订为coauthored。判断“自主”看是谁做出关键决定，不看是谁最后输入公式。

5. 多Agent架构：四专职Agent、两个受控模块

角色

输入与职责

输出

不允许做什么

PreparationAgent 备课

题干/图、授权参考、bank版本；prepare或route_review

教学包/局部路线补丁、数学核对待办、检验候选

不读取用户身份、不自称人工审题、不直接显示答案

DiagnosisAgent 诊断

已确认且有效输入、当前任务图、证据与探针结果

数学判断、竞争假设、证据ID、候选探针及分支

StrategyAgent 教学策略

诊断、目标、用户求助意图、剩余预算与披露账

干预类型、支架等级、允许事实、保留决策、下一产物

不绕过探针上限、不批准未知解法、不能把已提示改为自主

AssessmentAgent 学习评估

新任务题干/核对rubric、锁定计划、最终答案

规划/执行分判、逐条证据与unknown

不看学生旧诊断画像、不输出教学提示、不决定独立资格

Renderer 表达模块

只读获准事实、学生可见历史与单个动作

简洁中文+LaTeX

不接收完整私有解法/未来rubric

Guard 校验模块

候选输出、任务核对资料、允许/保留边界

数学风险、泄露判定、实际披露ID

不自己向学生发送文本、不单独决定完成

这些角色可以用同一个模型，不需要六个不同模型。Agent指有独立目标、上下文边界、结构化结果和调度节点的职责单元；不需要自由群聊、自主联网或多轮互辩。

5.1 默认编排方式

默认采用原生TypeScript显式编排器+持久节点日志，而不是先引入重型Agent平台。状态与schema是本项目最有价值的部分，应自研；成熟渲染、框架、数据库和测试能力复用开源。LangGraph.js保留为候选适配器，不作为当前基线的隐含必装依赖；在能安装和通过恢复测试前不宣称已集成。以后切换编排库不得改教学契约、预算与验收。

选题 -> PreparationAgent -> Guard核对 -> 缓存教学包 确认输入 -> DiagnosisAgent -> [必要时PreparationAgent.route_review] -> StrategyAgent -> 代码PolicyGate -> Renderer -> Guard -> [一次受控重写/复核] -> 事务提交 -> 显示 无提示检验 -> 锁定计划 -> 最终答案 -> AssessmentAgent -> Guard -> 代码计算独立性 -> 报告

PolicyGate由代码执行：身份、版本、有效证据、两探针上限、允许披露集合、用户直接讲解请求、时间/token预算、任务曝光、重复提交与状态转换。模型不能自行写数据库或调用网络工具。

5.3 恢复与成本

每个节点保存input_hash、模型/提示版本、结果和状态。崩溃后仅在输入哈希和run lease仍有效时复用已完成节点；未知是否完成的远程调用允许重做但可能重复计费，不声称供应商exactly-once。数据库提交保证一次：输出、事件、曝光和安全响应原子持久化后才返回。一个会话只允许一个活动工作流；删除/到期撤销lease，迟到结果丢弃。

7. 核心示例（自拟，不冒充高考题）

题：f(x)=x+1/x，x>0，讨论单调性与最小值。

两名学生都写f′(x)=1+1/x²。系统先记“这一行无效，原因未定”，问“只看倒数项，你怎样说明它的求导依据？”；发送之前保存两种预期回答与反证。

学生甲说“倒数的导数就是正的”：支持概念缺口，采用幂函数表示桥梁。学生乙说“写成x的负一次方，求导应该有负号，我抄错了”：支持执行缺口，邀请自查继续，不再讲基础导数。学生丙导数正确但不会从符号推单调：走策略连接桥梁，不重复求导。

若学生用均值不等式求最小值，允许此路线，并指出单调性仍需要独立论证。不得因为参考解法是导数就判AM–GM错误。

检验使用面积9的矩形周长最小问题：先独立建立P=2(x+9/x)，再给最小值12及边长3。它只是近迁移，不是远迁移或长期掌握证据；重新检验使用不同目标/条件、经核对的新任务，不能只改面积数字。

8. 复用策略与质量门槛

具体仓库、已有证据、待实测项和A/B落地点见本包reuse.md。当前可依据已有本地源码/许可快照评估react-markdown、KaTeX、诊断提示素材等；新一轮在线核验失败，不声称当前最新版本或安全审计已经完成。

优先复用：Next.js/React页面与服务端能力；react-markdown+remark-math+rehype-katex公式渲染；Zod结构约束；SQLite驱动；Vitest与Playwright测试。每个依赖在D1/D2完成安装、锁版本、许可证及传递依赖检查和目标环境烟测，形成reuse-lock.json。失败不能用“GitHub star高”覆盖。

不直接fork完整教学Demo：界面类似不代表具备诊断、撤架、曝光追踪、完整题库和恢复机制。SocraticAI/Mr.Ranedeer/诊断Skill只作设计材料；Pix2Text是手写备选不是默认额外Python服务；Texo/texify等需要额外适配与许可检查，不纳入默认依赖。SymPy不直接处理学生字符串，也不新增独立服务；数值代入不是任意数学证明验证。

9. 竞争力、不足及验证方式

竞争力来自“可被评委当场反证但仍成立的教学能力”：同错不同教；能力已会不再教；前问调用困难会搭桥；异解被尊重；帮助撤去仍能完成新任务；老师为什么这样问有证据可查。多Agent数量本身不加分。

主要不足和对策：

自动备课可能错：参考依据+独立检查+抽样人工核对；未知保留，公开就绪率和失败题，不把needs_review隐身。 台阶过细削弱策略：先学生规划、适应性跳阶、路线来源和实际披露记账。 诊断看似聪明但只是猜：竞争假设、预注册分支、反证更新、两次探针预算；统计误诊和unknown比例。 多Agent贵而慢：分角色预算、准备缓存、限制上下文、无需调用的确定性事件不调模型；测真实总耗时和token。 短期通过不能证明学会：规划/执行拆评，近重复单列，延迟测验未做即not_evaluated；若获授权可追加24–72小时新任务观察，不作为10天默认已完成事项。 小样本容易自证：强苏格拉底基线、同预算、盲化人工判例、错误类型与分母公开；模拟学生只用于工程回归，不作真人学习证据。

10. 交付与验收闸门

约10天交付可运行Web、题库导入清单、受控多Agent、全链路交互、撤架检验、教师依据、历史/删除、故障恢复和测评记录。至少所有P0用例通过、正式题库范围核对完成、关键数学样本人工检查、真实模型烟测完成；严重数学错误、私有答案泄露、独立性洗白均阻断发布。

若正式题库、模型凭据或真人授权未到，开发可用标记明确的夹具继续，但对应交付仍为blocked/not_run，不算完整验收。时间不足时增加日历缓冲或精简装饰，不静默删除能力。
