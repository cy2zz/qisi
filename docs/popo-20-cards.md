## 一、这个项目在做什么

启思 AI 是一个给高三学生用的数学思维教练。它不是"把答案拆成很多问句"，而是：

1. 学生先自己写思路
2. 系统诊断他卡在哪 —— **同一种错法，不同原因要给不同帮助**
3. 只给必要的最小提示，保留学生该做的那部分判断
4. 最后用一道**没见过的新题**检验是否真的学会 —— 原题做完不等于学会

---

## 二、为什么分成 A / B 两条线

**A 线管"外面的东西"**：脚手架、数据库、题库导入、手写/语音输入、独立检验页、证据报告、历史与删除、部署。

**B 线管"教学本身"**：四个教学角色（备课 / 诊断 / 策略 / 评分）、工作流内核、教学页、教师页。

**每张卡都是"纵向切片"**，不是前端/后端分工。一张卡里通常同时包含页面、后端接口、数据库改动和测试。20 张卡里 A、B 各 10 张。

## 三、B01–B10：每张卡做什么、怎么验证

### B01 领域契约、四 Agent 壳和工作流内核

**大白话**：打地基。把规格里 48 份"数据长什么样"的约定变成**代码能强制执行的检查** —— 模型吐出来的东西格式不对就直接被拒，进不了系统。同时把"备课/诊断/出主意/打分/写话/检查"拆成**六个各自独立的角色**，每个角色有自己的说明书和测试，不是一个提示词里写六个名字冒充。还做了一个**预算账本**（模型调用超次数或超时就停，不许绕过）。

**怎么验证**

```bash
npm --prefix server run typecheck
npm --prefix server run lint
npm --prefix server run test
```

看 `test/agents/at13-role-isolation.spec.ts`（9 项）。它证明的是"**不是一次调用伪造四个阶段**" —— 会检查每个角色调用时用的说明书确实不同、上下文确实不同。

**进展**：代码完成，未经第二人复核（AT13 证据文件未产出）

### B02 备课 Agent、核对、图与检验任务池

**大白话**：给一道题"备课"。生成一张**路线图** —— 哪些步骤是"必须都会的"（AND），哪些是"两条路走一条都行"（OR），并检查有没有绕成死循环。做**缓存**：备课结果绑定"题干内容 + 模型 + 提示词版本"，**题干一改旧结果自动失效**，不靠谁记得去清。做**检验题候选池**：每道题至少两道检验题，没核对过的、给这个学生看过的、同一类用过的都选不了，而且**每条为什么不可用都列出来**。

最要紧的一条：把「格式对 ≠ 数学对」**写进了类型系统** —— 有个字段恒为 false，代码路径上不可能变成 true。

**怎么验证**

```bash
npm --prefix server run test -- test/preparation
```

47 项。AT05（结构缺陷必须落入待复核）、AT06（题干一改旧包失效）、AT07（数学对不对不能自动认证）。

**进展**：代码完成，未经第二人复核

---

### B03 真实教学轮与可见页面

**大白话**：学生提交一步之后，后端不是"一个提示词"，而是**四个角色排队干活**：

1. **诊断** —— 判断这步数学上对不对、错的话可能是什么原因，并要求列出"如果我的猜测对你会看到什么；不对你会看到什么"
2. **策略** —— 决定给什么帮助、给到几分、哪些话能说
3. **一道代码关卡**（不过模型）—— 检查"要说的超没超出允许范围？这条思路是不是已经问过两次了？"
4. **表达** —— 把批准的内容写成给学生看的中文
5. **守卫** —— 再看一遍有没有把答案漏出去
6. **全过了才提交**；不过就重写一次，再不过就不给学生看

**怎么验证**

```bash
npx playwright test --grep @B03        # 需要应用跑起来
npm run test:e2e:task -- B03
```

AT14（真实模型调用记录）、AT15（新会话只展示题干与自主输入、不预先泄露完整步骤）、AT27（发给表达角色的请求里不含完整解法、未来评分标准、私有诊断原文）。

**进展**：代码完成。**AT27 已可验证；AT15 需要应用跑起来；AT14 的实质已实测过但正式证据未产出**

### B04 证据诊断和有区分力的探针

**大白话**：让诊断更准。区分"不知道""表述不清""计算失误""概念误解"，**同一种错法不同原因分开判**。探针（追问）必须能区分至少两种解释，发出去之前先写好"预期看到什么"和"什么会推翻我的猜测"。**同一条思路上最多问两次**，而且换目标名字绕不过去。

**怎么验证**：AT19–AT23（5 项，含 unit / integration / model_review 三层）

**进展**：**未开始**。develop 上有一份 B04 是 A 写的，状态 in_progress

### B05 七类策略、动态台阶与路线归属

**大白话**：七种教学手段（条件检查 / 目标反推 / 表示转换 / 调用前结论 / 边界反例 / 错误定位 / 示范后撤架），按证据选，不是轮流展示七种模板。支架分五级，学生会的能跳过，有效异解可以走自己的路线。**记录"是谁做的关键决定"** —— 学生自己定的、老师插的、共同改的，分开记，不能一边把每步安排好一边说学生独立规划。

**怎么验证**：AT16/17/18/24/25/26/60（7 项）

**进展**：未开始

### B06 输入修订与教师决策依据

**大白话**：学生改自己的输入时，保留旧版和新版，并**让依赖旧版的诊断结论失效** —— 但绝不抹掉"已经给过的帮助"。做教师页：老师能看到"为什么这样问"的完整证据链（证据 → 假设 → 探针 → 选择 → 实际给了什么 → 后续观察），但**看不到模型的隐藏思维链、系统提示或未来题目的答案**。

**怎么验证**：AT12/29/39/40/41

**进展**：未开始

## 六、现在的真实状态

**已经能跑的**：命令行全套检查、B01/B02 的全部单测、B03 的契约与投影测试。

**已经实测过的**：真实模型链路 —— 完整四角色跑通，6 次真实调用，模型 `gpt-5.5-2026-04-24`，token 全部为精确上报。诊断正确找出"概念/执行/策略"三类原因，策略正确选择"表示转换桥梁"。最后一轮被守卫拒绝没有展示给学生 —— **这是对的**，守卫在把关。

**还不能做的**：界面端到端验证。差三样，都在 A 的写集里：

1. 会话读取接口 `GET /api/session/:id` 未交付
2. 教学模块未接入应用装配
3. 入口传入的是开发夹具的假会话号，不是数据库里真有的会话

**实测发现的两个真实缺陷（尚未修复）**：

1. **每次模型调用都会返回 400。** 适配器要求提示词里必须出现 "json" 字样，而规格包的角色提示**通篇没有这个词**（实测 4 份各 0 处）。任何按规格接真实提示词的人都会撞上
2. A 那边记录的"模型服务不可用"是**误诊** —— 实际就是上面这个 400，只是适配器把 HTTP 状态码吞掉了，看不到真因
