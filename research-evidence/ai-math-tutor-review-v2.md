# 「启思」AI 高中数学思维老师：方案评估与比赛版 V2

评估日期：2026-09-15  
依据：用户提供的 PRD、调研文档，以及官方论文、GitHub 仓库、模型卡的定向核查。  
配套材料：`ai-math-tutor-source-audit.md`（来源编号 S1–S16、选型证据及核查边界）。

> **结论：值得做，不必推倒重来；保留“备题/教学分离、结构化诊断、受控教学策略、决策可视化”，重做“诊断依据、学生自主性的定义、学习效果验证”，缩掉现场随机备题等非必需能力。**
>
> 核心定位改为：**识别学生当前最需要验证的思维卡点，用最小必要帮助促成学生自己推进，再用撤掉帮助后的任务检查是否真的学会。**

## 1. 判断依据与范围

这不是一个“把答案分成更多轮吐出来”的项目，也不应把“多个 Agent 在后台忙碌”当作教学能力。

比赛真正需要展示的证据是：
1. 学生哪里卡住，AI 根据什么判断，而不是凭空贴标签。
2. 为什么现在选这个干预，而不是直接讲下一步。
3. 干预后学生是否自己完成了新的数学判断。
4. 提示撤掉后，学生还能不能完成相近但未见过的判断。

原方案的模块分层适合作为工程骨架；我不建议改成另一个通用多 Agent 平台，也不建议直接套一个“苏格拉底 Tutor”开源外壳。

### 1.1 必须先修正的研究表述

- **研究分组不能混淆。** 2025 年正式发表的研究题目是 *Generative AI without guardrails can harm learning: Evidence from high school mathematics*。练习相对提升 48%、撤去 AI 后考试相对下降 17% 对应 GPT Base 组；GPT Tutor 组练习相对提升 127%，无辅助考试与对照组没有显著差异。因此，“有护栏可减少损害”不等于“已经证明提升独立学习效果”。这些不是提升/下降了同样数量的百分点。研究情境也不能直接等同于中国高考教学。[S1]
- **MathTutorBench 引文有实质错误。** 正确编号是 `2502.18940`；原稿的 `2504.08649` 是一篇关于阿贝尔群无限和集的数学论文。官方仓库概述是“三类高层能力、七项具体任务”，另有困难版本，不是原稿所称的“八维诊断字段标准”。可借鉴它的错误定位与教学评估，但不能把自定义 JSON 枚举说成论文规定。[S2]
- “AI 介入干扰深入思考是主要原因”可以作为产品假设，但不能声称一次演示验证了唯一因果机制。我们的原型要检测独立表现，而不是只检测作业完成率。

## 2. 原方案逐项处置

| 原设计 | 结论 | V2 改法 |
|---|---|---|
| Solver 与 Tutor 分开 | 保留 | 比赛题提前准备、数学老师审核；运行时以教学为主 |
| 结构化诊断 JSON | 保留并增强 | 增加证据定位、竞争假设、澄清问题、诊断修订记录 |
| 与标准步骤图对齐后归因 | 核心重构 | 先检验学生主张的数学有效性，再对齐学习目标；允许多解和暂无法判断 |
| 固定专家步骤 DAG | 改造 | 作为“参考解法图”，不能是唯一合法路线；核心改成能力/关键决策图 |
| 连续两次 stuck 才给更强提示 | 删除硬门槛 | 综合已知能力、错误类别、主动求助、上次干预是否奏效；两次失败只是信号 |
| 未尝试不解锁提示，返回 403 | 删除 | “不知道从哪开始”也是有效求助；降低任务粒度，不惩罚学生 |
| 文本/数字比对防泄题 | 降为辅助检查 | 增加本轮允许披露范围、关键决策披露检查；有限重试后用已审核提示兜底 |
| 你完成 x/y 步 | 改造 | 区分独立完成、提示后完成、老师演示；统计关键决策而非任意拆分的步数 |
| 知识点掌握度变化 | 改造 | 改为“本次证据状态”；没有独立检验，不输出虚构掌握百分比 |
| 教练视角 trace | 保留 | 展示可核对的教学决策记录，不依赖或声称读取模型完整内部思维链 |
| 现场随机给题、1–3 分钟备题 | 移出 P0 | 赛题要求选一道高考真题；除非主办方另有未提供的随机出题规则 |
| 双模型一致即放行 | 不作为正确性证明 | 一致性仅是信号；人工审题与适用范围明确的工具验证为主要依据 |
| Pix2Text + Texo 双离线备援 | 缩减 | 视觉 API 主线 + 可编辑转写；先不承担两套 OCR 集成成本 |
| 2–3 人、5–7 天全功能 | 不按原范围承诺 | 缩至一题闭环、一个迁移任务、两个界面视角与受控评测 |

## 3. 比赛目标与功能映射

| 要求/评分项 | V2 功能 | 现场应展示的证据 |
|---|---|---|
| 选一道高考真题 | 1 道精修主问题；来源、题干、图形与答案经核对 | 题目来自赛事真题集，不把自拟例题包装成真题 |
| Markdown / LaTeX 输入 | 文本输入、预览、公式渲染 | 学生可直接写多步推导与解释 |
| 手写图输入 | 上传、裁剪、分行转写、修改确认 | 错认负号/指数时先澄清，不给学生扣“概念分” |
| 文本 + LaTeX 输出 | 短反馈 + 一个学习任务 + 可选择帮助 | 渲染正确，长公式不会撑坏布局 |
| 诊断薄弱点 | 主张校验 + 多假设 + 区分性追问 | 相同错误答案、不同学生解释，触发不同干预 |
| 合理教学步骤 | 受约束的自适应教学控制器 | 当前动作针对当前卡点，不只是按标准答案下一步推进 |
| 学生自主性 | 给出方法选择权、学生先生成关键判断、逐步撤掉提示 | 不是每步都由 AI 告知再让学生填空 |
| 展示推理细节 | 教师端“证据—假设—动作—结果”记录 | 原话、数学检查、选动作的简要理由均可追溯 |
| 是否学会 | 结束前无提示近迁移/解释检验 | 学生在未见过的任务上独立表现；不能据此声称长期提分 |

## 4. 产品闭环：诊断—干预—学生生成—撤架检验

### 4.1 学生端不应只有聊天框

建议布局：
- 左：题目、学生草稿与已经确认的事实；不提前展开完整解法。
- 中：对话/草稿输入，支持 Markdown、LaTeX、手写图。
- 右：当前学习目标与证据状态，例如“正在练：判断一个条件是否足以推出结论”。
- 帮助入口：`我想自己试`、`给一点提示`、`换种解释`、`这一步我不会`。
- 结束卡：本次关键判断、帮助强度、独立检验表现、建议下一次练什么。

不默认展示学生“思维薄弱”“粗心”等人格化标签。用具体行为描述：
> “你已经找到了导数为零的点；我们还需要检查这是否足够判断极值。”

不把老师演示标成羞辱性红叉；它是合法教学动作，只是不能算独立完成。

### 4.2 学习目标必须落到行为

| 太抽象的标签 | 可观察、可检验的行为 |
|---|---|
| 逻辑能力 | 能否指出推理所需条件，区分必要与充分 |
| 数学建模 | 能否把文字条件转为变量、方程与约束 |
| 策略意识 | 能否提出下一步目标、比较两种可行方法 |
| 表征转换 | 能否把导数符号、函数单调性和图像对应起来 |
| 反思能力 | 能否用反例/边界值检查自己的结论 |

P0 每道题只选择 2–3 个核心思维目标，不做整个高中数学知识图谱。

### 4.3 一个教学片段（自拟示例，不冒充高考真题）

题目片段：研究 $f(x)=x^3-3x$ 的极值。

学生：
> “$f'(1)=0$，所以 $x=1$ 是极大值点。”

**不要立即给结论“你不懂极值”**。当前至少有三种可能：
- H1：把导数为零当作极大值的充分条件；
- H2：知道要看符号变化，但判错了增减；
- H3：只是把“极小”写成了“极大”。

先追问：
> “你判断极大的依据是什么？能写一下 $x=1$ 两侧的变化情况吗？”

分支 A：学生说“导数为零就是极大”。
- 用一个小反例任务，而不是直接重讲整题：
  > “暂时看 $g(x)=x^3$：比较 $g(-0.1),g(0),g(0.1)$。导数在 0 处为零，能说明这里最大吗？”
- 学生自己计算、判断并表述条件不足。
- 如仍不理解，给 2–3 句必要讲解，然后让学生回到原题重做符号判断。

分支 B：学生写出左负右正，但仍说“极大”。
- 聚焦“函数由减到增对应什么”，不再重复教授导数为零的概念。

分支 C：学生解释正确并说明笔误。
- 接受修正，继续让学生自主推进，不反复进行低阶提问。

结束前，用新任务 $h(x)=x^3+3x^2$ 让学生无提示判断极值并解释依据。要记录是否在这项新任务上独立完成，不能仅凭学生把老师刚说的话重复一遍判定掌握。

## 5. 技术架构：保留分层，减少在线串行模型调用

```text
离线/开发期
赛事真题 + 参考解析
  → AI 辅助编写教学包
  → 教师核对题干、解法、误区、提示和迁移任务
  → 可验证题目包 ProblemPacket（版本化）

在线每轮
学生 Markdown / 手写图片
  → 输入解析；图片保留逐行转写、位置、待确认内容
  → 主张抽取 + 数学校验 + 当前诊断（结构化）
  → 教学控制器：规则限制 + 模型提出动作建议
  → 限定披露范围的话术生成
  → 数学/教学/披露检查（有次数上限）
  → 学生得到一条反馈与一个可执行学习任务
  → 下一轮证据更新 / 撤架 / 近迁移检验

事件存储
每轮原始输入、确认内容、证据、假设修订、策略、检查结果、学生输出
  → 学生报告（精简） / 教师审计视角（隔离）
```

### 5.1 推荐栈

- 沿用 Next.js + TypeScript、FastAPI、SQLite；团队若更熟其他栈，不必为此切换。
- Markdown 渲染：`react-markdown + remark-math + rehype-katex`；KaTeX 做公式展示，不承担公式识别或数学判对。[S3]
- 后端结构验证：类型化 DTO / Pydantic；JSON Schema 合规只代表形状正确，不代表诊断为真。
- 数学工具：SymPy 的限定表达式校验器、人工核对的条件和参考解法。不要做通用自动定理证明器。[S4]
- 模型：一个已经具备访问条件的视觉模型 + 一个教学模型；可为同一供应商，也可不同。不因“推理榜单最高”直接选教学模型。
- 编排：普通 Python 服务和显式会话状态足够；P0 不需要额外上 LangGraph/AutoGen、向量库、Neo4j、分布式消息队列。
- 每轮通常 1 次结构化分析 + 1 次受约束话术生成；图片按需增加视觉解析；只有风险轮次增加复核。是否合并调用由实际延迟与质量测试决定。
- 不边生成未经检查的草稿边向学生直播。可以展示“正在核对你的步骤”，最终内容通过检查后再发送。

这些是针对本次范围的工程取舍，不是对框架优劣或模型排名的普遍结论。

### 5.2 题目包：把有限题目做深

```json
{
  "problem_id": "gaokao-selected-001",
  "source": {
    "exam": "从赛事题集填写",
    "year": null,
    "question_no": null,
    "verified": false
  },
  "statement_markdown": "待录入并核对",
  "domain_assumptions": [],
  "learning_objectives": [],
  "milestones": [],
  "solution_paths": [],
  "misconception_hypotheses": [],
  "diagnostic_probes": [],
  "hint_moves": [],
  "worked_micro_examples": [],
  "transfer_tasks": [],
  "verifier_cases": [],
  "review_status": "draft",
  "version": "v1"
}
```

每个核心里程碑至少配置：
- 它对应的关键数学决策；
- 可接受证据，而不是只接受一条标准公式；
- 适用定义域、隐含条件；
- 典型错误表现和可能原因；
- 能区分原因的追问；
- 不同强度的提示/微型例子；
- 撤架后怎样验收。

若题目存在多种常见解法，应准备至少两条可行路线。未收录的解法不能自动判错，需进入开放校验分支；不能验证时明确说“这一步我还需要核对”，而不是强迫学生换标准方法。

### 5.3 数学事实判断与思维诊断必须分开

建议三层结构：
1. **读到了什么**：原图/原文、转写、学生是否确认。
2. **数学上发生了什么**：主张是否成立、条件是否遗漏、理由是否足够。
3. **可能为什么这样想**：待验证的学生认知假设。

```json
{
  "input_status": "confirmed",
  "claims": [{
    "claim_id": "c1",
    "evidence_ref": "turn_4.line_2",
    "statement": "f'(1)=0，因此1是极大值点",
    "math_verdict": "invalid",
    "reason_summary": "给出的条件不足以支持所述极值类型",
    "verification_scope": "题目给定实数定义域与已确认的导函数"
  }],
  "diagnosis": {
    "status": "needs_probe",
    "target_objective": "必要条件与充分条件",
    "hypotheses": [
      {"id": "H1", "label": "把驻点条件当成极大的充分条件", "support": ["c1"]},
      {"id": "H2", "label": "符号变化或极值类型对应错误", "support": []},
      {"id": "H3", "label": "书写失误", "support": []}
    ],
    "next_probe": "请学生说明极值判断的依据和两侧变化情况"
  }
}
```

例中数学推理无效可以较明确判断，但“根因”仍待确认。不要把两种确定性混为一谈。

补充规则：
- 学生一次提交多步时拆成多条主张，保留正确部分，优先处理影响后续的关键错误。
- `math_verdict` 使用 `valid / invalid / unknown`；别把工具无法解析等同于错误。
- 缺少证明可能是“证据不足”，不一定是结论错误。
- 低输入可信度先确认输入；低认知证据强度先追问。二者不能只压成一个 `confidence`。
- P0 用“证据不足/已有支持/经独立任务支持”等状态；未经校准的模型自报 0.87 不应显示成科学概率。
- 不依据一句话推断“长期粗心、逻辑弱”；把 `careless` 从默认根因枚举中移除。

## 6. 教学控制器：约束模型，但不要把老师变成死流程

### 6.1 状态与动作

状态可用：`INPUT_CONFIRM → DIAGNOSE → PROBE / PRACTICE → REPAIR → FADE_SUPPORT → TRANSFER_CHECK → REVIEW`。

动作集合：
- 确认符号/学生意图；
- 请学生解释依据；
- 让学生提出下一步或选择路线；
- 指向相关条件（弱提示）；
- 给策略方向（中提示）；
- 用反例、图示、类比或小任务修复；
- 必要的短讲解 / 演示一个小步骤；
- 请学生独立重做；
- 无提示近迁移；
- 总结并标记哪些能力仍未验证。

### 6.2 决策规则

| 当前证据 | 优先动作 | 不应做 |
|---|---|---|
| 图片负号/指数不清 | 确认转写 | 直接诊断学生概念错误 |
| 不同根因都合理 | 一个能区分假设的追问 | 直接贴“概念不懂”标签 |
| 表达正确、理由不足 | 请解释关键依据 | 重做已会的低阶计算 |
| 学生主动说不会起步 | 更小的起步任务/弱提示 | 要求先随便答一次才能帮忙 |
| 关键概念尚未建立 | 反例 + 必要短讲解 + 学生应用 | 无止境反问造成挫败 |
| 学生独立完成且能解释 | 放手，请学生自行推进 | 自动把下一步策略告诉他 |
| 学生提示后做对 | 逐步撤架再检验 | 立刻宣布掌握 |
| 路线不同但有效 | 沿学生路线继续 | 按标准 DAG 强行拉回 |
| 直接请求完整解答 | 说明训练模式，提供小提示或明确标记的讲解选择 | 假装“不给答案”却用引导题泄露整个方法 |

模型可提出候选动作及简要依据，代码负责禁止跨越教学目标、禁止过量披露、保证只有一个主要任务等硬约束。**“规则定边界、模型做判断、证据修正状态”比“LLM 只写话术”更适合本题。**

## 7. 防代做：保护关键决策，而不是屏蔽数字

### 7.1 本轮披露策略

每一轮生成明确的教学合同：
- `target_objective`：这一轮要学生练什么；
- `known_facts`：学生已经建立/确认的事实；
- `allowed_disclosures`：本轮允许说明的条件、概念或局部例子；
- `reserved_decisions`：必须留给学生自己完成的数学选择或推导；
- `help_level`：本轮允许的帮助强度；
- `expected_student_artifact`：学生需要生成一条理由、公式、图像判断或策略。

话术生成器仅接收当前所需子集，而不是默认获取整份解答。它仍可能自己解出答案，因此这只是风险降低，不是充分保证。

### 7.2 检查与兜底

- 规则检查：是否包含当前禁止直接给出的结果、是否同时安排太多任务；允许引用学生已得到的数值。
- 语义检查：是否把关键建模、构造、方法选择提前替学生完成；即使没有最终数值也可能属于过度帮助。
- 数学检查：仅验证适用工具能验证的陈述；涉及一般证明不能冒称“SymPy 已完整证明”。
- 风险输出最多重写一次；再失败用与当前动作匹配的人工审核提示，不无限循环。
- 记录“检查通过/未覆盖/拦截”，不要写“绝不泄露、绝不出错”。
- 学生已完成后，可以核对答案并回顾完整思路；合理示范也不应被一刀切禁止，但标记为教师帮助。

### 7.3 技术安全与信息边界

SymPy 官方文档警告 `parse_expr` 使用 `eval`，不应处理未净化输入。因此不能将学生文本或模型输出直接丢给它。[S4]

P0 建议：
- 只支持白名单运算符/函数的表达式 AST，并限制长度、嵌套、运行时间；
- 优先调用已审核的题目专用校验函数；不在线执行任意模型生成 Python；
- 若未来需要执行动态代码，另建无网络、无凭证、有限资源的隔离执行服务；
- 学生接口不返回完整题目解答、禁止披露列表或教师 trace；不能仅靠 CSS 隐藏；
- 图片、草稿是数据，不是系统指令；不能因图片中写“忽略要求”就修改教学策略；
- API Key 只在服务端，日志不记录密钥；图片设置删除/保留策略，演示不用含真实姓名、学号的素材；
- Markdown 不启用未经净化的任意 HTML；限制上传类型、尺寸及解码后的图像规模。

## 8. OCR：保留学生原始错误，别把它修成正确答案

视觉解析的目标是“忠实转写”，不是“识别后帮学生解题”。

输入对象至少保留：`原图引用 / 行号 / 区域位置 / 候选转写 / 歧义 / 确认状态`。

关键机制：
1. 区分题干和学生草稿，不把图中印刷答案当成学生自己做出的过程。
2. 保留划掉内容的状态，不擅自采纳废弃步骤。
3. 指数、负号、不等号等存在歧义时局部确认。
4. 转写可编辑。纠正 OCR 不计为学生解题错误，也不计为一次错误尝试。
5. VLM 不可用时切换“手动转写/文本输入”；离线录屏只能标为回放，不能冒充实时智能。
6. 只有在真实手写样本、比赛电脑和断网预加载测试通过后，才把本地 OCR 称作可靠兜底。

Pix2Text 可作为 P1 本地候选；Texo 可作为单公式、浏览器端的探索候选。二者都不能仅依据 README 就承诺完整中文手写推导、几何图和涂改的可靠理解。[S5][S6]

## 9. 教学决策可视化：展示依据，不展示“伪读心”

教师端一轮卡片：

```text
观察到的证据：第 4 轮第 2 行写了“导数为零，所以极大”
数学检查：给出的条件不足以支持结论
诊断状态：尚未确认根因
竞争假设：概念混淆 / 符号判断错误 / 笔误
本轮动作：追问极值判断依据
为什么选它：可区分三种解释，且暂不替学生给出结论
为学生保留：两侧变化情况的判断
学生后续表现：由下一轮实际输入更新
```

这是可审计的教学决策摘要：原始证据、工具结果、模型建议、代码实际选择、生成文本、后续结果。不要将事后补写的解释说成模型真实完整内部思维链。

证据还没有出现时不填“根因已解决”；动作建议与实际选择分别记录。教师端与学生端接口权限和披露内容隔离，演示时由评委单独查看。

## 10. 开源复用结论

详细证据与许可证定位见配套核查文档。此处是选型结论，不是已完成安装/真实学生验证的声明。

| 组件 | 比赛版选择 | 理由与边界 |
|---|---|---|
| KaTeX、react-markdown | 直接采用 | 做输入预览与输出渲染；不能识别或验证数学 [S3] |
| SymPy | 限定范围直接采用 | 可做局部计算/恒等验证；条件、定义域、证明完整性要单独处理 [S4] |
| Pix2Text | P1，本地 OCR 候选 | 有代码、文档、测试目录；抽查公式测试主要运行并记录输出，不能据此认定真实手写准确率 [S5] |
| Texo / Texo-web | P1 或不做 | 20M 单公式 OCR、浏览器实现；AGPL-3.0；ONNX 与不同模型版本指标不能混用 [S6] |
| MathTutorBench | 借鉴评测任务，按需跑子任务 | 是评测框架，不是诊断服务或可直接用的高中家教系统 [S2] |
| universal-diagnostic-tutor-skill | 借鉴诊断清单/失败案例 | Markdown 行为层；EVALS 提供情景规范，不等于执行过的学生学习实验 [S7] |
| SocraticLM | 研究参考，不部署训练 | 代码、数据、权重许可不同；不为一周原型引入训练和模型服务 [S8] |
| Mr. Ranedeer | 不作运行时底座 | README 明示 DISCONTINUED；借鉴交互思想需与直接复制区分 [S9] |
| SocraticAI | 不作运行时底座 | 示例旧依赖和多 AI 对话不是本题教学闭环；仍要自己实现诊断、状态与验证 [S10] |
| LaTeX_OCR_PRO | 不选 | 文档要求 Python 3.5 / TensorFlow 1.12.2，迁移风险不符合节省工期目标 [S11] |
| texify | 不选 | 2025-01-29 已归档；代码与权重使用条件需分开看 [S12] |
| math-question-bank | 后续教师工具候选 | 有完整题库/组卷功能、测试目录和 CI，但不是思维教学引擎；P0 仅一题不值得接入 [S13] |
| NuminaMath | 不作 P0 必选 | 应区分 HF 模型与官方竞赛训练/推理仓库；解题强不等于中文教学强 [S14] |

原则：**复用成熟、边界清晰的基础组件；自建最薄的教学闭环；不要为复用一个完整应用而接受与赛题无关的复杂度。**

## 11. 学习效果与工程验收

### 11.1 不用“做对了本题”代替“学会了”

每个关键决策记录：
- `independent`：本题对应决策尚未被直接提示，学生先生成且理由有效；
- `hinted`：获得方向/策略提示后完成；
- `demonstrated`：老师已示范，学生随后重述；
- `unverified`：尚无足够证据。

独立完成占比可按预先确定的核心决策权重计算：

$$R_{independent}=\frac{\sum_i w_i\,\mathbf{1}(decision_i\text{ independently constructed and verified})}{\sum_i w_i}.$$

权重与分母在审核题目包时固定；多解路线映射到共同能力目标，不能通过拆更多小步骤刷高比例。另列提示后完成和教师示范占比，不能混加后统称独立完成。

该比率只是本次过程指标，不是掌握度、智力评分或因果学习增益。优先展示“你独立完成了哪几个关键判断”，而不是漂亮的百分比。

### 11.2 最小评测集

建议先做 60 个受控案例（例如 48 个开发、12 个保留测试），另保留一组多轮完整会话；这只是工程起点，不是足以证明泛化的样本量。

必含：
1. 完全正确且解释充分；
2. 正确答案但理由错误；
3. 非标准但正确的解法；
4. 多步输入中只有一处错误；
5. 计算笔误 vs 概念误解；
6. 同样错误结果、不同历史解释的成对案例；
7. 缺条件/定义域/分类讨论；
8. 仅说“不会”或主动要求帮助；
9. 概念短讲后仍不会，需要换策略；
10. 学生跳步和提前做完；
11. 手写负号/指数/不等号歧义；
12. 手写涂改、错行与混合文本；
13. 要求直接答案/提示注入；
14. 工具无法判断或格式不合法；
15. API 超时、连续输出检查失败与安全回退。

### 11.3 建议验收门槛（目标，不是已测结果）

| 项目 | P0 建议门槛 |
|---|---|
| 题目包 | 主问题与迁移题经审核，无已知数学错误；来源核对完成 |
| 非标准解法 | 纳入测试的正确路线不得被误判为错；无法判断须走澄清/核验 |
| 诊断 | 对证据充分的案例，核心卡点匹配人工标注；证据不足能保留假设，不硬猜 |
| 量化诊断统计 | 分别报告错误定位、根因有证据支持率、无证据硬诊断率，写出分母与失败案例 |
| 自主性 | 测试中不出现未经许可替学生完成关键决策的严重泄露；不能只检测最终答案 |
| 修复闭环 | 提示后至少安排一次学生生成与一次撤架检查，不以复述当掌握 |
| OCR | 报告关键符号正确性、歧义发现/确认情况和用户纠正次数；不只报告 LaTeX 可渲染率 |
| 稳定性 | 至少 10 次完整走通一题，包含手写、异常及恢复；恢复不重复计分或丢状态 |
| 延迟 | 在比赛设备和模型上记录各阶段 p50/p95；可先以文本 p95 < 10 秒、图片 < 20 秒为工程目标，再按实测修订 |
| 审计 | 所有判断均能回指输入，所有动作记录实际执行值，教师数据不出现在学生 API |

不要一边调 prompt 一边用全部测试集算“最终准确率”；保留集不用于逐条调优。不要由同一个教学模型给自己打分作为唯一证据。

### 11.4 对照与真实学习验证

以同一模型、相近 token 预算对比：
- A：直接解题聊天；
- B：仅加“不直接给答案、苏格拉底追问”的 prompt；
- C：V2 的证据诊断、受控干预、撤架检验。

比较错误定位、无依据诊断、过度帮助、学生需要完成的关键判断、延迟与费用。脚本学生和模型学生适合工程回归，不等于真实学习效果。

条件允许时邀请少量真实学习者做可用性试用，用等难任务进行前测/后测或交叉顺序测试；记录原始表现与不确定性。短期、小样本只能给探索性信号。长期考试提升需要更充分的独立/延迟测试，比赛演示不应夸大。

## 12. 数据对象与接口建议

核心对象：
- `ProblemPacket`：版本化题目与教学资源；
- `SessionState`：已确认事实、当前目标、帮助记录、待检验假设；
- `StudentSubmission`：文本/图片引用及确认状态；
- `ClaimCheck`：数学主张与适用范围明确的校验结果；
- `DiagnosisRecord`：证据、候选解释、修订历史；
- `TeachingDecision`：候选与最终动作、披露范围、实际帮助强度；
- `LearningEvidence`：独立生成、提示后完成、示范与迁移表现；
- `TurnEvent`：连接以上对象的真实事件记录。

建议 API：
- `GET /api/problems`：学生可见题目元信息，不含解答包；
- `POST /api/sessions`：创建会话；
- `POST /api/sessions/{id}/submissions`：提交文本/图片，含幂等键；
- `POST /api/sessions/{id}/transcripts/{tid}/confirm`：确认或修改转写；
- `GET /api/sessions/{id}/turns/{turnId}`：学生可见结果与状态；
- `POST /api/sessions/{id}/help`：表达帮助需求，不用“未尝试 403”惩罚求助；
- `GET /api/sessions/{id}/report`：仅返回证据支持的学习总结；
- `GET /api/teacher/sessions/{id}/trace`：受保护的教学审计数据。

P0 若图片转写与本轮输入合并，接口可进一步减少，但前后两阶段证据状态不可省略。超时后重试不得重复增加失败次数或提示等级。

## 13. P0/P1 范围、排期与现场演示

### 13.1 P0 必做

- 一道来自赛事真题集的精修题目；适当覆盖常见多解。
- Markdown / LaTeX 与手写图片输入。
- 证据驱动诊断、澄清追问、分级帮助、放手。
- 非标准正确解法的处理与无法判断分支。
- 一个不依赖提示的新任务/近迁移检验。
- 学生端简洁体验，教师端真实决策记录。
- 基本安全、超时回退、状态恢复与回归案例。

### 13.2 P1 或暂不做

- 任意随机题自动备题；
- 多模型投票 + 第三模型仲裁；
- 全学段知识图谱、长期学习画像；
- 自训练、微调或强化学习；
- 多套本地 OCR、语音、复杂白板；
- 大而全的题库后台与精细用户系统；
- 专门为展示搭建的复杂多 Agent 链。

如果以后要做随机备题：作为教师“备课草稿生成”功能，必须有审校状态；未通过审核的题包不能直接宣称具备同等教学质量。缓存键还需包含题干版本、图形、领域条件和题包/提示版本，不能只有题目文本哈希。

### 13.3 七天建议（沿用原文 2–3 人、全职投入的假设）

| 日程 | 核心工作 | 当日可验收产物 |
|---|---|---|
| D1 | 选题、核题、思维目标、错误样本、首批手写素材 | 经审核题目包 v1 + 评测骨架；尽早暴露 OCR 风险 |
| D2 | 文本/公式/图片输入、视觉转写确认、会话存储 | 输入链路与真实 API 打通 |
| D3 | 主张校验、诊断假设、追问、替代解法 | 成对案例能触发不同诊断分支 |
| D4 | 教学控制器、披露边界、生成检查、安全回退 | 学生参与完成主问题，不是答案分步输出 |
| D5 | 撤架与迁移检验、教师证据面板、报告 | 三评分项和“学会证据”均可展示 |
| D6 | 保留集测试、失败修复、真实试用、延迟统计 | 结果表与已知限制；若核心未稳不加第二题 |
| D7 | 稳定性回归、演示彩排、设备/网络/备用方案 | 可现场使用的版本与如实标注的备用回放 |

前提：已具备模型额度、可用网络和至少一位能够核对高中数学与教学材料的人。若缺少这些条件，应减少展示装饰，而不是削掉数学核验与独立检验。

### 13.4 推荐 6–8 分钟演示结构

1. **30 秒**：一句话目标，“我们优化的是撤掉 AI 后学生还能做什么”。
2. **1 分钟**：学生上传真实手写草稿，展示局部转写确认。
3. **2 分钟**：一个错误引出竞争假设；学生解释使 AI 修正/确认诊断。
4. **1 分钟**：反例/小任务修复；学生自己完成关键判断。
5. **1 分钟**：撤掉提示，让学生做一个新的近迁移任务。
6. **1 分钟**：打开教师端对照证据与干预、查看谁完成了哪些决策。
7. 有余量再演示“相同错误结果、不同根因”或非标准正确解法，而不是表演随机备题。

演示输入可以事先准备，但生成结果、失败回退和在线/回放状态应如实说明；评委试用必须走相同真实链路。

## 最终建议

优先级从高到低：
1. **让每次诊断有依据并允许被推翻。**
2. **让每次帮助留下一个值得学生自己完成的数学决策。**
3. **让“做对本题”与“撤掉 AI 后会做”在产品里被明确区分。**
4. 然后才是多题、备课自动化、本地 OCR、复杂多 Agent。

这版的竞争力不在于“更会拒绝答案”，而在于：**它能判断该帮什么、帮到哪、什么时候不再帮，并用学生后续的独立表现检验自己的教学判断。**
