# Chat 安全反馈恢复｜B07 局部优化

日期：2026-09-30；基线：qisi-3.1；授权：用户“优化吧”，不含提交、推送、部署或子 Agent。

## 需求与验收

现状：chat 多种系统校验失败共用“请把依据再写一行”，容易把系统故障表现为学生证据不足，形成教学死循环。

- FR08 / AT22：同一 canonical goal 两探针达到上限后不继续追问，包括 ask + probe=null；不通过修改目标或计数绕过，改为当前帮助深度内的解释、低风险帮助或明确待定。
- FR09 / AT25：尊重帮助选择。系统不能安全给出本轮反馈时，明确不是判定学生答错，指向已有“局部解释/直接讲解”入口，不强迫补一句、不自动升级 L4。
- FR10 / AT27–28：Guard 获得已确认 revision 的证据和决策含义；Renderer 不接触私有参考、完整诊断或 Guard 笔记。一次预算内重写 + 复核，仍不通过则中性退出；unknown 不受施压变为 accept。
- FR15 / AT45、ST07 相关边界：所有尝试使用共享 BudgetLedger，7 calls / 24000 input / 8000 output / 90s；节点25s。失败、Schema修复和重写均计数；未知用量保守估计；取消/超时的迟到内容不得提交。

## 非目标

不关闭 Guard，不把 unknown 变成正确/掌握，不扩大批准披露范围，不重置探针，不自动改题。未通过内容不得流式输出。
不改前端、公共响应 Schema、依赖、DDL、Assessment 或四角色架构。复用现有帮助按钮、节点审计和最终事务。
本轮不宣称完整 B07 故障恢复、真实 MySQL 8.4、真模型质量或真实学生学习效果验收。

## 2026-09-30 续轮：等价选法不应绑定参考索引

用户反馈同一兜底仍出现。只读原请求调查定位为互补选法误判及两次策略失败，不能用改善文案代替修复。新增验收意图：按学生自己的索引核对正确等价表示；真实漏因子仍拒绝；完整正确作答确认收尾而不是要求重复补依据。原题系数80作为合成回归oracle，不硬编码生产答案。

本续轮完成有限真模型抽样但未通过稳定性验收：当前v2两例正式批次1通过/1失败，额外反例诊断采样通过仅说明存在波动。人工教学评估、原会话全链路与独立复核仍未完成。实际结果和安全不变量以 qisi-sdd-v3/changes/B07.md 续轮及 artifacts/acceptance/B07-20260930-equivalent-route/ 为准。


## 2026-09-30 续轮：先核对答案，避免引用协议误拦

新增验收：空history的完整正确作答应先独立核对最终答案，再检查过程和等价方法，确认已有正确解法而非继续补依据；答案恰好相同但过程错误仍不能完成。模型引用格式错误属于系统协议故障，不是学生数学错误。

本轮支持服务端证据编号还原，现有共享一次修复覆盖诊断引用/Schema/已知语义错误；不改canonical Schema，不放松Guard，不增加预算。实际新提示answer-first-evidence-v1真模型单批2/3通过：正确80与错误过程80通过对应oracle，漏组合数样本因连续诊断/策略校验问题仍安全退出。该失败保留为待解决稳定性项，不能宣称所有反馈已经稳定。原业务会话端到端、人工教学评估/独立复核尚未完成。
