# 启思学生端 UI

为中国高三学生打造专注的数学学习工具，而不是通用 AI 聊天、学校门户或游戏化儿童应用。

## 从学习时刻出发

设计或修改代码前：

1. 阅读仓库 `AGENTS.md` 以及相关 PRD、任务、契约和验收用例。
2. 明确当前学习时刻：选题、尝试作答、确认手写、定位卡点、接受帮助、独立检验或回看历史。
3. 写明学生此刻要完成的任务、可能承受的情绪压力、主操作、帮助/披露风险以及必须覆盖的恢复状态。
4. 阅读 [references/design-language.md](references/design-language.md)，获取视觉系统与交互模式。

不要从后台模板出发。应将当前数学决策和学生自己的产物置于视觉中心。

## 产品不变量

- 采用 PC 优先、H5 完整适配的响应式设计。先在 1280–1440 px 建立题目与演算并行的主工作区，再重排到 360–390 px 单栏；两端共享业务语义，H5 不得隐藏或降级必要操作。
- 一次只聚焦一个可执行问题，同时保留题目、学生草稿和当前目标入口；不要把屏幕切成三个等宽面板。
- 明确区分 `尝试作答`、`看一点提示`、`解释这里` 和 `直接讲清楚`。当帮助会改变独立检验资格时，绝不能把它设计成无关紧要的视觉开关。
- 使用不同视觉标记区分学生已确认产物、教师提供的帮助和共同完成内容。不得用路线完成百分比冒充掌握程度。
- 学生确认不确定行之前，手写转写始终是待核对内容。不得把 OCR 修正表现成学生的数学错误。
- 中性呈现 `unknown`、歧义和可重试的系统故障。普通错误不是危险状态，不得羞辱学生。
- 独立检验期间按契约冻结首次计划/作答，不泄露正误、提示、未来任务或私有评分标准。
- 使用简洁、直接的中文。避免居高临下的夸奖、励志口号、过度追问和“AI 老师正在思考”式拟人文案。

## 实现规则

- 使用项目现有的 React 19、Vite、Tailwind CSS 和 shadcn/ui 技术栈。增加依赖前优先复用项目组件和设计令牌。
- 将 shadcn/ui 视为具备无障碍行为的基础组件，而不是成品视觉风格；必须根据本项目主动重塑样式。
- 设计令牌使用 CSS 变量。采用语义化 HTML、清晰可见的键盘焦点、减弱动效支持，以及至少 44 px 的触控目标。
- 通过项目安全的 Markdown/KaTeX 链路渲染数学内容。不得启用不可信原始 HTML；长公式应横向滚动，不要缩小到无法阅读。
- 契约中存在相应状态时，覆盖加载、空状态、准备中、待确认、离线/重试、已完成和不可用状态。
- 不得将密钥、私有题解、未来检验材料、教师专属依据或模型隐藏推理放入浏览器代码或模拟数据。
- 添加字体、图标、动效库或其他依赖前，核对许可、包体积影响、维护情况和仓库复用规则。

## 审查标准

实现类任务至少验证：

- 1280 和 1440 px PC 宽度，确认信息密度、双主区关系、键盘效率和按需展开区域；
- 360 和 390 px H5 宽度，确认单栏重排、软键盘/输入行为、安全区边距和全部核心操作可达；
- 键盘导航、焦点顺序、对比度、减弱动效、中文换行和长 KaTeX 公式溢出；
- 项目中真实存在且与改动相关的单元测试、类型检查、lint、构建以及视觉/e2e 检查。

必须区分自动化检查、fixture 审查、专业视觉审查和真实学生观察。精美截图不能证明教学效果。
