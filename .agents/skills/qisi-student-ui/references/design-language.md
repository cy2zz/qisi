# 启思学生端视觉与交互语言

## 核心概念：答题纸 × 数字训练舱

界面要同时传达三件事：这是认真做数学的地方；学生的思路是主角；技术在后台提供支撑而不是表演自己。

保留中国学生熟悉的答题纸秩序、草稿批注和演算节奏，但不复刻传统教辅、学校官网或考试系统。数字感来自精确的状态轨道、局部动态和清晰的信息层级，而不是霓虹赛博或“AI 紫色渐变”。

目标气质：**清醒、锋利、可信、有一点反常规**。避免幼稚，也避免制造备考焦虑。

### 标志性视觉记忆

使用一条“思路轨道”作为跨页面母题：它可以是 PC 非等分布局中的中轴、H5 边缘的一条竖向细线，或题目状态间的连接痕迹。轨道节点代表已发生的关键决定与帮助披露，不代表掌握百分比。

轨道旁可以出现短批注、来源标记和状态切口，使界面像正在被学生书写和修订，而不是已经排版完成的电子教材。

## 色彩

以暖纸面和深墨色建立长时间阅读基础，用少量高纯度颜色承担明确语义。

```css
:root {
  --qisi-canvas: #f1eee5;
  --qisi-paper: #fffdf7;
  --qisi-ink: #18212b;
  --qisi-ink-muted: #66707a;
  --qisi-line: #d8d2c5;
  --qisi-coral: #ff5b3d;
  --qisi-cobalt: #2864dc;
  --qisi-jade: #087f70;
  --qisi-amber: #a56a12;
  --qisi-danger: #bd3446;
}
```

- `paper/ink`：题干、作答和长文本的主场。
- `coral`：当前焦点、批注、需要明确确认的帮助动作；不要铺满大面积。
- `cobalt`：可探索、可继续的交互与系统路径。
- `jade`：学生已确认的产物、独立完成证据和稳定成功。
- `amber`：不确定、待核对、OCR 模糊，不等同于错误。
- `danger`：删除、隐私、安全等真正危险动作；普通数学错误不用危险红。

珊瑚色主要用于轨道、描边和大号焦点，不直接承担小字号正文；实心控件应重新检查前景色对比度。颜色不能成为唯一状态编码，始终搭配文字、形状或图标。若增加夜间模式，使用低眩光深蓝灰而非纯黑，并实际检查公式、图片和手写预览。

## 字体与排版

- 中文正文优先保证高密度阅读清晰，字号不低于 16 px，行高约 1.65；题干正文宽度约 28–36 个汉字。
- 短标题可以使用有性格、许可明确的中文展示字体；批注可少量使用屏幕友好的楷体/手写感字体。不要把手写字体用于长题干、按钮或公式。
- 数字、计时与题号使用等宽数字特性，营造精确感，但不做“数据大屏”。
- 数学公式保持 KaTeX 字体体系和足够留白。长公式横向滚动或分行，禁止整体缩得难以阅读。
- 外部字体必须核实许可并优先自托管；未核实前使用可靠回退栈，不依赖运行时公共 CDN。

## 空间与形状

- 采用非对称布局和明确留白，桌面端可用约 5:7 的题目/思考区关系，不使用三个等宽后台面板。
- 圆角保持克制：输入区和底部操作可柔和，题纸与轨道更适合小圆角、切角或直线。不要给每段内容都套一张圆角卡片。
- 纸面可使用极淡网格、题号定位标记、页边线或噪点纹理；装饰不应降低文字与手写图片清晰度。
- 阴影短而硬，像纸张轻微离开桌面；避免大面积玻璃拟态和漂浮胶囊。

## 核心页面构图

### 做题与教学

PC 是主设计面。使用题纸与思考区约 5:7 的非等分双主区，思路轨道位于两者关系处；题目与必要图保持稳定可见，作答、诊断和教学反馈占据主要操作空间。当前目标与已发生记录通过轨道、可收起侧栏或抽屉按需呈现，不要复制传统“左题目、中聊天、右进度”的三栏后台。优先支持键盘输入、公式快捷键和高效焦点切换。

H5 将同一流程完整重排为单栏，从上到下：

1. 可折叠的题目上下文条，保留题号、当前小问与返回题干入口。
2. 当前焦点区，只呈现本轮一个问题或需要确认的动作。
3. 学生演算区，优先展示自己的计划、公式、图片和修订。
4. 固定但不遮挡内容的输入/操作坞，包含软键盘输入、公式快捷项和拍照。
5. 帮助入口与提交动作在视觉和文案上分开；高影响帮助在底部面板中再次说明后果。

PC 与 H5 使用相同的状态、动作和披露语义。响应式变化只调整空间组织，不得通过隐藏功能制造两套学习规则。

### 音视频播放控件

- 音频和视频播放器都必须提供连续音量调节与独立的静音/恢复按钮，不能用单个静音按钮冒充音量控制。
- PC 端提供始终可通过键盘到达的音量滑杆，支持方向键细调，并以文字或无障碍数值表达当前音量。滑杆可以在聚焦或打开音量面板后出现，但不能仅依赖 hover。
- H5 端使用至少 44 px 的触控入口，在弹层或底部面板中提供足够长度的滑杆。全屏与横竖屏切换后，控件不能被安全区或浏览器工具栏遮挡。
- 静音前保存最近一次非零音量；取消静音时恢复该音量。音量滑到 0 时，图标、`muted` 状态和无障碍文案必须同步。
- 不自动以有声方式播放。尊重用户最近一次会话内设置，但不要在未说明时跨用户共享音量偏好。
- 部分 H5 浏览器不允许网页直接修改系统输出音量。实现时应做能力验证：受限平台使用原生播放器或系统音量控制并保留静音能力，不能显示一个实际上不会改变音量的假滑杆。
- 测试至少断言媒体元素的 `volume` / `muted` 与控件同步、静音恢复正确、键盘与触摸可操作，以及全屏控制仍处于可视范围。

### 手写确认

原图与转写行建立清楚对应。待确认行使用琥珀色虚线和“不确定”标签；点选后放大对应图片区域，允许直接修改。确认按钮应说明“确认转写内容”，不要写成“答案正确”。

### 独立检验

视觉应比教学态更安静：减少建议色和可探索动作，突出“先写计划”和当前未提交状态。帮助按钮仍可见，但明确会结束本次独立资格。提交前不出现对错色彩、庆祝动效或隐性提示。

### 复盘与历史

围绕“我当时怎么想—哪里得到帮助—后来能否独立完成”组织时间线。避免只给分数、连续天数和完成率。证据不足显示“尚未验证”，不要用灰色勋章暗示失败。

## 动效

- 页面进入只做一次有编排的淡入/位移，常规反馈约 160–240 ms。
- 可以让思路轨道延伸、批注下划线写入、纸面轻微归位；成功反馈克制，不放烟花和彩带。
- 等待模型时展示真实阶段文本和安静的轨道脉冲，不伪造逐字思考或流出未校验内容。
- 支持 `prefers-reduced-motion`，重要状态不能只靠动画表达。

## 中文交互文案

语气像可靠的年轻教练：短、直接、尊重学生时间。

推荐表达：

- “先写你准备怎么做”
- “把卡住的位置圈出来”
- “看一点提示”
- “解释这个地方”
- “直接讲清楚”
- “这行我没看清，请确认”
- “目前证据还不足，先不下结论”

避免表达：

- “亲爱的同学，让我们一起探索吧”
- “太棒啦！你又战胜了一道题！”
- “AI 正在深度思考……”
- “你怎么又算错了”
- 用“完成 80%”暗示学生掌握了 80%

## 明确不要做

- 企业后台式侧边栏、三张统计卡和大面积表格作为学生首页。
- 全屏聊天气泡主导做题过程。
- 紫蓝渐变、发光机器人、粒子宇宙等通用 AI 视觉。
- 红金榜单、卷轴、毛笔字等表面“中国风”。
- 幼儿卡通、拟人吉祥物、过量 emoji 和连续签到压力。
- 每个区域都使用同样的白色圆角卡片。
- 用动画、颜色或赞美提前泄露答案正确性。

## 交付时说明

给出视觉方案或实现时，应说明：当前学习场景、PC 主路径、H5 重排、关键状态、帮助披露、无障碍处理以及真实执行的验证。未观察真实学生时明确写 `real_student_observation: not_run`。
